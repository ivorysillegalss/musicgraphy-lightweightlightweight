## R-106 专辑空间漫游视图（设计参考：Album Atlas® → 看板卡 S2-4）

### 参考站是什么

- Album Atlas®（albumatlas.vercel.app）：**「Interactive WebGL experience to explore and
  preview an artist's albums」**（站点 og 自述）——搜索一位艺术家，进入以其专辑封面为
  展品的三维「图集」空间，漫游、点选、就地试听预览。WebGL 实现（页面入口 = Search Artists）。

### 设计原理与思路

1. **专辑集合 = 一个可漫游的「场所」，不是一张列表**：封面从网格单元升维为空间中的展品，
   「回顾收藏」从翻页变成「回到现场」——与 Musicgraphy「线索回响」的情感目标同构。
2. **空间位置承载语义**：陈列与聚类本身就是叙事（年代、流派、时期的分组感），
   不需要文字解释就能被感知。
3. **探索与验证不分离**：漫游中就地试听/点开，不跳出场景——浏览路径零打断。
4. **搜索是入口不是主体**：先搜艺术家进入空间，之后交给漫游——「找」与「逛」分层。

### 借鉴映射与需求草案方向

- 功能准入自查：主要贡献「更好回顾」与「更好整理」（可视化盘点收藏）；不引入推荐/发现语义。
- **草案方向**：Collection（或单艺术家切片）的「空间视图」评审案——封面按年代×流派聚类陈列的
  可漫游画布；点选即详情页；载体与 R-103/专项二同批裁决（WebGL 引擎 vs CSS 3D vs Canvas，
  与 React 接入形态一次定）。
- 数据零新增：视图只是 Collection 的又一种 View（Topster=View 先例，禁第二套数据）。

### 红线适配（实施前逐项核对）

- 资产自托管零 CDN（乙-5 维持）：3D 引擎一律构建进 dist，禁外链；
- DD3 URL 即状态（乙-1 维持）：漫游位置/焦点专辑须可分享可后退（query 或 hash 编码）；
- 内存四纪律（乙-10 维持）：空间取数 LIMIT≤60 分页供给，封面流式；
- WebGL 性能与 RSS 为观察指标（IM-30 甲-7），评审案中重测基线。

### 开放问题

载体选型（WebGL/Three.js vs CSS 3D vs Canvas——与 R-103 React 载体合并裁决）；
空间语义选哪种轴（年代×流派 vs addedAt×颜色轴 vs 无语义自由陈列）；
移动端降级形态（回退网格）。

## R-107 档案的声音身份与叙事（设计参考：Chiara Luzzana → 看板卡 S2-5）

### 参考站是什么

- Chiara Luzzana（chiaraluzzana.com）：获奖声音设计师的个人作品集站点——「A creator of
  sound. From pure noise to melody, everyday life is her Symphony.」「Everyday life is
  her sound」（站点原文）。声音本身是站点的主角：滚动即叙事即播放，排版极简（大字、高对比）、
  整站像一件作品而不是一份简历。

### 设计原理与思路

1. **声音即身份**：不靠图片堆砌，用「听感」定义一个人——个人站点最有力的表达材料可以是声音。
2. **滚动即叙事**：滚动进度 = 叙事进度 = 播放进度，交互本身就是讲故事。
3. **克制排版驱动沉浸**：元素极少、留白极大，沉浸感来自专注而非堆料——与本项目
   「low cognitive load」UI 原则天然相容。
4. **第一人称的个体性**：整站是一个「人」的声音，不是一家公司的官网——个人档案产品的
   语气也应该是「我的档案」，不是「本系统」。

### 借鉴映射与需求草案方向

- 功能准入自查：文案层贡献「更好回顾」（个人档案的个体温度）；声音层贡献「更快记录」
  （详情页试听确认）与「更好回顾」（回响的听觉线索）。
- **草案方向（拆两层，分别评审）**：
  - **a 文案叙事层（低风险，纯文案零架构）**：全站文案第一人称气质梳理——空态、回响卡、
    flash 提示、页脚署名等处语气统一（「这是我的档案」而非「欢迎使用本系统」）。
  - **b 声音层（评审案）**：详情页/回响卡的就地试听或音频点缀；**默认静音、显式开启**
    （隐私红线 + 不打扰）；音频源合规与自托管评估先行——外部预览源涉上游调用
    （限流纪律乙-4）；无合规源则本层降级为「只做 a 层」。
- 与 R-103/专项二同属「感官层」（动效 + 声音），建议合并一次评审。

### 红线适配

隐私红线（匿名可关闭零外发）：任何音频默认关闭、用户显式开启；上游调用走既有串行限流；
零 CDN——音频文件若自托管一律进本地资产。

### 开放问题

音频源（外部 30s 预览 URL 的合规与稳定性 vs 无音频纯文案层）；声音点缀的触发场景
（进入详情？回响卡出现？）；与动效专项统一的「感官层」开关形态。

## R-108 翻箱（Crate Digging）浏览模式（设计参考：cratedigger.js → 看板卡 S2-6）

### 参考站是什么

- cratedigger.js（risq.github.io/cratedigger/ · repo = github.com/risq/cratedigger，MIT）：
  **「3D vinyl records exploration & crate digging experience, using WebGL with Three.js」**
  （README 自述）——一只三维黑胶箱，封面侧脊密集陈列，翻动唱片、抽出一张看正面
  （PREVIOUS / SHOW / NEXT），模拟唱片店翻箱（crate digging）的实物体验。

### 设计原理与思路

1. **物理隐喻 = 收藏的实物感**：黑胶箱、侧脊、抽出——把「数据浏览」翻译成「摸得到的东西」，
   个人档案的情感温度正来自这种实物感（自己那只唱片箱）。
2. **侧脊封面即界面**：密集陈列天然适合大量封面的快速翻检——单位屏幕信息密度高但认知负荷低
   （形态符合现实经验）。
3. **不带目的的翻找**：翻箱的乐趣 = 无明确目标的遇见——这正是「线索回响」的主动版：
   用户自己翻出记忆，而不是系统推送。
4. **单张聚焦动作**：SHOW = 从一摞里抽出一张细看——「广度浏览」与「深度查看」一个手势切换。

### 借鉴映射与需求草案方向

- 功能准入自查：贡献「更容易找回」（非目的性找回）与「更好回顾」；翻箱是浏览形态不是新数据。
- **草案方向**：Collection 的「翻箱视图」评审案——横向翻页式封面陈列（**2D/CSS 3D 即可成立，
  WebGL 非必须**——实物感来自交互隐喻而非 3D 渲染）；键盘 ←/→ 翻动、Enter 抽出详情
  （衔接 keyboard-flow 岛屿先例）；「随机一张」入口（翻箱的遇见感 → 回响卡）。
- 与 R-104 封面墙下拉限制联动：翻箱 = 天然的分页式浏览，可作为无限瀑布流的替代形态之一。
- Topster=View 先例：视图不建第二套数据；URL 即状态（翻到的位置可后退可分享）。

### 红线适配

零 CDN（若引入 3D/动效库构建进 dist）；内存纪律 LIMIT≤60 分页供给；DD3 URL 即状态。

### 开放问题

2D 侧脊陈列 vs 真 3D 箱体（体量差一个量级）；与 R-104 的形态互斥还是并存；
移动端手势（滑动翻页）；「随机一张」与回响卡的入口关系。

## R-109 我的流派星图（设计参考：Every Noise at Once → 看板卡 S2-7）

### 参考站是什么

- Every Noise at Once（everynoise.com，Glenn McDonald）：数以千计的音乐流派的**算法散点地图**
  ——位置由音频特征相似度决定，近邻 = 听感相近；主页格言 **「YOU HAVE NOT YET HEARD YOUR
  FAVOURITE SONG」**；每个流派名即点即听（per-genre 艺术家地图 / 1D 列表另页）。
  素净 HTML、极端信息密度——数据本身就是设计。

### 设计原理与思路

1. **相似度 = 组织维度**：流派不按字母排，按「听感距离」排——「那张类似 xx 的电子」
   这类模糊记忆有了空间化的找法。
2. **密度即信息**：一屏放下整个宇宙，全貌本身就是价值（谁与谁相邻一目了然）。
3. **零层级直达**：每个点/标签即点即达，没有二级导航。
4. **诚实工具感**：不装饰数据，UI 素到极致——与本项目 lightweight / personal archive
   气质相容，也最省实现。

### 借鉴映射与需求草案方向

- 功能准入自查：贡献「更容易找回」与「更好整理」——把「我的流派宇宙」画成认知地图，
  找回 = 地图上点一下。**锚定 Find/Organize，不是推荐引擎**（产品红线：不是推荐引擎；
  Discover 优先级最低——本需求不引入任何「猜你喜欢」，只呈现用户自己档案里已有的
  Genre/Tag 结构）。
- **草案方向**：「我的流派星图」评审案——以本档案 Genre×Tag 集合为对象的散点视图；
  相似度用**本地共现计算**（同收藏共现——SQLite 自算，associations 域 getAssociations
  先例，零外部调用优先；若要外部 audio features 须限流 + 缓存专项评审）；
  点击节点 → 直达筛选结果（URL 即状态 ?genre=..&tag=..，与 chips 同语义）。
- 布局离线预计算（脚本先例 = color-extract CLI），不在线跑力导向。

### 红线适配

DD3 URL 即状态；内存纪律（个人库流派/Tag 数远小于 60，天然达标）；零外部调用优先
（隐私红线）；数据全部本地派生（与自托管零 CDN 一致）。

### 开放问题

个人库流派/Tag 数量小（数十级）时散点图的表达力（是否退化为聚类分组视图）；
共现相似度 vs 颜色轴/年代轴的多维选择；空态（Tag 很少的档案）呈现。

## ② Chiara Luzzana 实现原理拆解（配套卡 S2-9 · 需求 R-107）

### 实现原理（证据级）

- **壳与叙事**：Webflow（jQuery 3.5.1 + webflow.js，CMS 形态）+ **locomotive-scroll 4.0.3**
  （平滑滚动 = 滚动即叙事的载体）；自定义光标 snippet；Google Analytics（我们不做）。
- **视觉核心**：**three@0.125.2** WebGL「球体」反应体——FBXLoader + fflate（FBX 3D 模型
  解压）+ 自定义 shader（jsSnippets/webglBall19/shaders.js + webglBall20/index.js）+ OrbitControls；
  站点大字排版文案（「A creator of sound. From pure noise to melody, everyday life is
  her Symphony.」）由 Webflow 排 + locomotive 滚动驱动。
- **声音核心（最有启发）**：**整站只有一份主音源 mainSound.mp3**（jsDelivr 外链），
  页面加载时 **零 `<audio>` 元素**——播放全部由 JS 动态创建（new Audio / WebAudio），
  即「声音素材极简 + 程序化编排」：不是塞一堆音频文件，而是一个声音资产的编程化演绎。
- **移动端**：页面含「Rotate your device, please.」——竖屏降级提示（体验门控）。

### 证据清单

浏览器实测 2026-11-15（script src 全清单 = 13 项，上列；resource entries 命中
mainSound.mp3；audio/video 元素 = 0；locomotive/webflow/AudioContext 全 true，
Howler = false）。页面文本抓取（标语与分区 PURity/oddity/noise/sound）。
音源编排细节（WebAudio 节点图）**待实测复核**。

## ③ cratedigger.js 实现原理拆解（配套卡 S2-10 · 需求 R-108）

### 实现原理（证据级——唯一有完整源码可逆向的一站，MIT）

- **数据**：唱片列表 = **JSON 数组注入页面**（demo 硬编码在 index.html：title/artist/
  cover/year/id/hasSleeve；封面 = Deezer CDN 400×400 URL）→ `cratedigger.loadRecords(data)`
  插件 API。**2 箱 × 每箱 24 张**（constants.js：nbCrates:2 / recordsPerCrate:24）。
- **建模**：每张唱片 = **薄长方体** BoxGeometry(100, 1.5, 100) 平移半宽（铰链在后缘）+
  MeshLambertMaterial + 封面贴图（TextureLoader）；侧脊立在木箱（wood.jpg 贴图）里，
  rotation.z = π/2 竖放。
- **状态机（灵魂）**：Record 四态 **pushed（半压）/ pulled（半抽，倾角 ±π/7）/
  shown（提起到 recordShownY=25）/ flipped（翻面到 y=110 + 旋转 π 露正脸 = 信息面板）**；
  全部用 TWEEN.js Quartic.Out 缓动（recordMoveTime 1000ms / infoOpenTime 700ms /
  cameraMoveTime 800ms）——「实物感」全部来自这套缓动编排，不是 3D 模型精度。
- **交互**：Raycaster 点选；**拖拽翻找**（grabSensitivity:6，delta=(baseY-mouse.y)/canvasHeight）
  + mousewheel 翻动；相机随鼠标视差（±0.25 系数）；PREVIOUS/SHOW/NEXT 键盘按钮。
- **后处理**：EffectComposer + DoFShader（景深虚化）+ FXAA——**默认关**（postprocessing:false），
  性能优先。
- **插件边界**：导出 init/startRender/loadRecords/unloadRecords/shuffleRecords/
  selectPrev/Next/flipSelectedRecord… 纯库形态，UI 面板自理。

逐行核对（2026-11-15）；上列常量/状态名/缓动参数为源码原值。

## ④ Every Noise at Once 实现原理拆解（配套卡 S2-11 · 需求 R-109）

### 实现原理（证据级——源页 3.5MB 全量指纹）

- **渲染形态（颠覆直觉）**：**不是 canvas/WebGL——纯 DOM**。主页 3.5MB 单页 = ~6291 个
  `<div class="genre scanme" preview_url="…" style="color:#a18807; top:10495px; left:984px;
  font-size:102%" onclick="playx(…)" title="e.g. 歌手《歌》">流派名</div>`——**坐标/颜色/
  字号全部服务端预计算后内联 style，静态 HTML 直出**；客户端零框架（原生 DOM+CSS +
  少量内联 JS）。单流派艺术家图页（engenremap-pop.html 158KB）同构：
  `.genre{position:absolute}` + `.genre[played]:before{content:"\266B"}`（播过标记 = 纯 CSS）。
- **音频**：每节点内联 Spotify 30s `preview_url` 数据属性，onclick 即播（playx()）；
  **scan()** 函数 = 自动扫听器（逐流派播放预览——著名的「流派扫描」）。
- **可访问性**：role=button + tabindex + onKeyDown=kb(event)——密集 DOM 也能键盘化。
- **自述与教训**：站点自述「was a long-running attempt at an algorithmically-generated,
  readability-adjusted scatter-plot…based on data tracked and analyzed for 6,291
  genre-shaped distinctions at Spotify **through 2023-11-19**」——时态已是过去式：
  **Spotify API 政策变动后站点进入维护态**（失效链接标注 class=broken、
  「if you get Spotify API credentials, you can try a DIY NRbG」）。
  **外部数据依赖的前车之鉴**——R-109 坚持本地数据自算的决策依据直接成立。
