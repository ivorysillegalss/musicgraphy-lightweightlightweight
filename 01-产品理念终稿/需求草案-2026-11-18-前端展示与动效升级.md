## R-113 全站字体与样式重做（ui-ux-pro-max 方法论重跑）

- **需求原文**：「首先就是当前在浏览器打开的默认100%的分辨率下 当前的字体过小」「并且字体之间的样式都太丑了」
  「重新通过uiuxpromax这个skill进行设计所有的样式」「可以充分利用react和js进行设计」。
- **现状锚点**：tokens.css 文字阶梯 = display 40px / h1 28 / h2 20 / h3 16 / **body 14 / small 12 / meta 11**
  （正文 14px 在 100% 缩放下偏小）；MASTER.md = token 唯一来源（07-前端设计包/design-system/musicgraphy/）；
  F0 期方法论 = ui-ux-pro-max 工作流（_downloads/ui-ux-pro-max-skill/ 克隆在档：.claude/skills/design 等）。
- **方向**：全站文字层级重定标（正文/小字/元信息全面上调）+ 字体间样式关系重设计（层级对比/行高/字距/
  深浅节奏），经 ui-ux-pro-max 方法论重新过一遍（design skill → MASTER.md 修订 → tokens.css 同步）；
  样式实现可充分用 React 与 JS（岛屿承载）。
- **开放问题**：字号阶梯具体值、是否引入第二条 display 字体、暗色模式联动、MVP 范围（全站 vs 先主干页）。

## R-114 主页信息密度减量（标签精简 + 瀑布流收敛）

- **需求原文**：「另外 当前主页下方的gener和年代的标签可以设置少一点 瀑布流不需要这么多」。
- **现状锚点**：筛选舱 Genre 恒展开一排 **18 项**、发行年份轴 **76 项**（S2-31 收起式）、Tag 轴 ~30 项、
  Favorite/颜色平铺；封面墙 = SSR 首屏 60 + 岛屿 autoLeft 3×60=240 自动追加后转手动（S2-30 口径）。
- **方向**：Genre/年份/Tag chips 展示数量减量（top-N + 其余收进舱内深筛选）；瀑布流首屏与自动追加页数收敛。
  ⚠️ 红线：chips=`<a>` DD3 URL 即状态语义不变（乙-1）；countAxes 计数与轴排除语义不动。
- **开放问题**：各轴 top-N 值、减量后"更多"入口形态、墙首屏张数与自动追加配额新值。

## R-115 顶部趣味入口带（星图/Topster 等置顶 + 动效）

- **需求原文**：「以及当前的星图 topster等功能界面可以放到最上面去 同样配合动销生成有趣的入口」。
- **现状锚点**：功能入口全部在页脚（S2-1 入口行：翻箱/流派星图/收藏全景/Topster×2/导出/观察池）——
  footer 纯出口语义（html.ts siteFooter）；主页顶部 = 回响卡 + SAVED VIEWS + TAG GOVERNANCE + 筛选舱。
- **方向**：星图/Topster/翻箱/全景等「探索类」入口自页脚升到主页顶部，做成带动效的趣味入口
  （T3 React 承载候选——S2-3 分层框架内落地）；页脚保留纯出口（数据主权）语义不破坏。
- **开放问题**：入口带形态（卡片/胶囊/图标组）、动效语言、占据高度与封面墙首屏的取舍、移动端形态。

## R-116 星图漫游化（地区 × 时间双维筛选 → 随机专辑 + 介绍）

- **需求原文**：「以及当前的星图的界面 我希望将他做成一个漫游的形式 做一个地区和时间的双维度可选筛选
  点击筛选之后 随机渲染出一个对应的专辑和介绍 具体的方案可以再设计」。
- **现状锚点**：/genres = genreMap 共现布局（流派+Tag 黑/琥珀节点，S2-24~26 交付）；/atlas = maplibre 地图
  （DR 系列交付，五态染色已修复上线）；数据面 = album_metadata（country 字段 B10 口径 105 行已补 /
  release_year 全量 / genres 全量）+ collection_record（added_at/listened_at）。
- **方向**：星图界面重构为「漫游」体验——地区 × 时间双维度可选筛选，点击筛选后随机渲染一张对应专辑
  + 介绍（数据全部来自本地档案，零外部调用）。**方案须评审案先行**（载体：React 岛屿；DD3：筛选/结果
  状态入 URL 可分享可后退；随机 = 服务端确定性与否须评审）。
- **开放问题**：双维值域（地区=国家字段口径?/大洲归组?；时间=年代档位?）、随机算法（纯随机 vs 加权）、
  与 /atlas 地图的关系（复用 vs 独立页）、「介绍」的内容构成（元数据+note+Tags?）、无匹配结果的空态。

## R-117 Hover 信息卡（详情不点进去）

- **现状锚点**：封面卡 hover = cover-meta（标题/艺术家/年份）显隐（W2-1）；详情数据面 = album_metadata

  （B10 同族元数据补全管线候选）——评审案须诚实给出「现有字段先上 / credits 数据扩展两阶段」路径。
- **开放问题**：hover 卡字段集（阶段一=现有字段;阶段二=credits）、触发延迟与触屏降级、与 R-113 新样式的合并节奏。
