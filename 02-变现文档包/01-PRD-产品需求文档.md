## 1. 产品概述

**一句话**：一座以"找得回"为第一美德的个人音乐线索库——记录时以零强制埋线索，找回时凭任何一根残缺线索在一屏封面之内重新"认出"，档案偶尔以确定性时间锚自己开口。

**核心闭环**：`听到音乐 → 记录(Record) → 积累/整理(Organize) → 找回(Find) → 回顾(Review) → 新的个人音乐记忆`
**优先级准绳**：`Find → Record → Organize → Review`（AGENTS.md §16；任何 P0 争议按此仲裁）。

**非目标（红线，详见 §8）**：不是流媒体、不是推荐引擎、不是社交社区、不是专业唱片数据库、不是统计仪表盘。

## 2. 用户与核心场景

同一用户在三种模式下使用产品（对应闭环三段）：

| 模式 | 场景（源自终稿 §2 / A3 场景清单） | 被满足的 P0 |
|---|---|---|
| 记录者 | "正在听一张好专辑，想在 3 秒内留住它"——不打断听歌 | FR-1 |
| 找回者 | "好像是一张 2010 年左右（**我听的时候**）的电子乐，封面是蓝色的，我加过'夜晚'标签" | FR-2 / FR-3 |
| 回顾者 | "年末想做 My Top 25""我为什么当年收了它？""大一那年冬天我都在听什么" | FR-2 / FR-4 / P1-1 / P1-2 |

**目标人群**：音乐档案爱好者——RYM 重度用户、Discogs 收藏者、Letterboxd（电影版印证）迁移者、听歌日记/手帐爱好者。

## 3. P0 需求规格（共识骨架六件套）

> P0 判定标准（终稿 §5.1）：缺一则核心承诺失效；同时通过"零新一级概念"审计。

### FR-1 记录路径：三捷径 + 确认层三件套 〔4/5 收敛〕

**用户故事**：作为记录者，我在不查资料、不打断听歌的情况下，几秒内把一张专辑存进档案，并顺手（可选）埋下未来的线索。

**规格**：
1. **输入端三捷径**：
   - 零输入候选：搜索框获得焦点且为空时，即显示候选——最近添加的艺术家及其专辑、最近搜索词；一次点击替代一次打字；
   - 粘贴识别：支持粘贴 Spotify / YouTube / Bandcamp / RYM 链接（提取 ID 或 slug）与 "Artist - Album" 文本串，自动匹配候选；
   - 已收藏前置标记：候选阶段即标注"已在你的 Collection"，防止确认后才发现重复。
2. **确认层（Add 弹层）**：
   - 默认态 = 完成态：**点击"添加"即落库**，一切补充字段不阻塞关闭；
   - Favorite 开关（心形）；
   - Tag 输入框：上方常驻"最近使用的 5–8 个 tag"（点击即挂）+ **输入时自动补全已有 tag**（防同义分裂，不可逆防线）〔裁决：A1 不可逆测试 + A2 落地形态〕；
   - Note 折叠框：折叠态 placeholder = **"为什么留下它？留一句当时……"**〔裁决案2：A5 提问 + A2 形态 + A1 placeholder 化；"不留下不可逆的缺席"〕；
   - 快捷听取时间：单选"刚刚（默认）/ 今年 / 去年 / 更早（年份粒度）"——就是 listenedAt 的录入界面，≤2 次点击、可跳过、可在设置中关闭。
3. **"先添加、稍后补"合法**：落库后详情页随时可补 Tag/Note/听期，允许两段式，不强迫一次完成。

**验收**：理想键盘路径 ≤5s（粘贴/零输入 + Enter）；普通路径 ≤3 步 / 15s；全路径 loading / empty / error 三态；失败不阻塞关闭。

### FR-2 渐进式筛选舱：chips + 实时计数 〔4/5 收敛〕

**用户故事**：作为找回者，我只记得一根残缺线索，通过不断加条件、看"还剩 N 张"，在一屏封面以内认出目标。

**规格**：
1. Collection 顶部常驻一行可展开筛选 chips；轴 = **Genre / 发行年份 / 我听的时期 / Favorite / Tag**（颜色轴见 P1-4）；
   - "发行年份 / 我听的时期"必须**并列且命名写全**，绝不共用控件默认值〔A3 半格偏差修正，5/5 二轮确认〕；
2. 每个可选值旁显示当前命中数 `Electronic (86)`；激活一个 chip，其余条件计数**立即**重算，计数为 0 的选项隐藏/置灰；
3. 已激活条件 = 可单独移除的深色 chip，移除即回流；**无"应用/重置"按钮**——状态即所见（试错式记忆的形态前提，最不可返工决策）〔A2 R3 + A3 风险3 + A4 P0-1 三方收敛〕；
4. **结果一律封面墙呈现**（cover-first 的贯彻），结果区同步显示总数"37 张匹配"〔A3 呈现规范，A1 吸收为规则〕。

**验收**：≤3 次筛选 + ≤10s 扫视 → 候选收敛到一屏（20–40 张）；全程封面可见；5000 张规模计数毫秒级。

### FR-3 全文检索：Note / Tag / 标题 / 艺术家 〔5/5 收敛，全场最强信号〕

**用户故事**：作为找回者，我记得自己写过的话（"备注里写了 reverb 很重"）或加过的标签，我应该能直接搜到它。

**规格**：Collection 内搜索覆盖 `标题 / 艺术家 / Tag 片段 / Note 片段`；Note 是四件套中唯一"只写不读"的字段——写下却搜不到不是取舍，是缺陷；实现为普通 LIKE / 全文索引均可（5000 条规模，AGENTS.md §11 禁止搜索集群）。

**验收**：Note/Tag 片段命中 < 200ms（5000 张规模）；搜索框与 FR-1 输入端为同一入口（双意图）。

### FR-4 数据决定三条（一行字，今天写进代码）〔5/5〕

| # | 决定 | 内容 | 依据 |
|---|---|---|---|
| D1 | **listenedAt 语义** | = 最近一次听的时间；默认 = addedAt；用户可改；允许年份级粗粒度 | A1 升 P0 + A3 判为"听的时期"轴前置依赖 + A4"趁早定" |
| D2 | **集合语义** | Collection Record 对 album 唯一；重复添加 → 转化提示（"已在你 Collection 中 · 去补线索 / 又听了一次"），**永不产生第二条记录或事件流**；"又听了一次" = 显式动作，更新 listenedAt | 裁决案1：三方反驳 + A5 仲裁 + A4 让步 |
| D3 | **封面主色** | 记录/导入时顺手提取，归入 12–16 离散色板，存为 Collection Record 派生字段（数据基建在 P0；筛选 UI 在 P1-4） | 裁决案5：三方多数进 P0 + A1 可回填性论证吸收为 UI 缓行理由 |

### FR-5 规模底座 〔5/5〕

默认中密度封面网格（cover-first）+ 虚拟滚动；**性能预算：5000 张首屏可交互 < 1s，滚动无白屏**——预算是验收标准不是功能。密度三档（大封面/中+标题/紧凑列表）与年份双分组（发行/听的）见 P1。

### FR-6 验收口径（全 P0 的完成定义）〔5/5〕

| 维度 | 口径 |
|---|---|
| 记录 | 理想键盘路径 ≤5s；普通路径 ≤3 步 / 15s |
| 记录可靠性 | 全路径 loading/empty/error 三态；失败不阻塞 |
| 找回 | ≤3 次筛选 + 10s 扫视 → 一屏（20–40 张）收敛；实时"还剩 N 张"；全程封面可见 |
| 线索埋点 | "当时/为什么" ≤2 次点击、可跳过、可全局关闭 |
| 规模 | 5000 张首屏 <1s |
| 数据主权 | 全量导出可用；外部元数据替换不伤用户数据（§4 二分） |

**北极星（团队内部，不设用户指标）**：**线索覆盖率** = 携带 ≥1 根个人线索（Note/Tag/听期）的记录占比，发布第一天起观测。

## 4. P1 需求（第一梯队）

| # | 条目 | 规格要点 | 验收 | 收敛度 |
|---|---|---|---|---|
| P1-1 | "一年前的今天"回响卡片 | Collection 顶部单张轻卡片，有周年记录才显示；无推送/单入口/单卡片/确定性锚，点开即详情页 | 有则显示、无则不显示；点击进详情 ≤1 步 | 5/5（裁决案2，中位 P1） |
| P1-2 | 详情页"记忆条"（个人档案区） | 详情页视觉分区：外部元数据区 / 个人记录区（第一人称重组："2023 年 8 月记录 · 听的时期：2023 夏 · Tags：夏天/海边 · 当时：青旅的天台"）；零新数据 | 分区清晰、个人区一行式摘要 | 3/5 独立发明 |
| P1-3 | 档案导出 | 全量 JSON/CSV（含元数据、记录、tag、note、听期）；**永久免费**（两方案红线） | 导出文件可完整重建档案 | 4/5 |
| P1-4 | 色板筛选 UI | FR-2 舱内加一排色块 chips（数据已在 D3） | 点色块即筛、计数联动 | 3/5 |
| P1-5 | 联想入口 | 详情页记忆条下方："同期听的 / 同天添加的 / 同 Tag 的其他专辑"（零新数据，激活扩散） | 三类联想各展示 ≤6 张封面 | 2/5（A4 提出 A3/A5 采纳） |
| P1-6 | Tag 轻治理 | 存量治理：季度级一行式合并提示（近形 tag："夜晚/夜间"；孤 tag："只挂 1 张"），点击选目标合并、引用重定向 | 提示不打扰（≤1 次/季度）；合并后旧 tag 消失、引用保留 | 2/5 |
| P1-7 | 重听动作 | 重复添加提示中的显式出口："又听了一次" → 更新 listenedAt（D1/D2 的落地界面） | 更新后"听的时期"轴与"那年今日"数据一致 | 3/5 |
| P1-8 | 键盘流 | `/` 聚焦搜索、`Enter` 添加首候选、`F` 快速 Favorite | 高频记录者单次 ≤3s | 2/5 |
| P1-9 | 歌名反查专辑 | 搜索命中歌曲名时显示"所属专辑：XXX，记录该专辑？" | 反查命中 → 一键进入 FR-1 确认层 | 1/5（A2 支线，性质判据通过） |
| P1-10 | 命名视图 | 保存当前筛选 chips 状态为命名视图（"深夜电子""大一那年"）；侧栏一键恢复；**只存查询状态，不存专辑集合**（裁决案4 附条件） | 命名/恢复/删除；与 Topster 同构、无第二套集合 | 2/5（A2/A3 vs A1，观察信号留档） |

**方案 B 的三处优先级调整**（透明记录，不违任何红线）：
1. **Topster v1 + 最小策展模型 + 导出图片**（终稿 P2）→ B 中提为 P1 末位打包项：它是零成本自传播面（A2："分享到社交平台的是作品图，不是产品"）——增长权重 0.25 的直接兑现。约束：策展数据模型（顺序可保存 + 副标题）必须与 Topster 首版**同期生效**（A5 底线）；不做自由画布/布局持久化。
2. **导出（P1-3）在 B 中前置到 Phase 2**：数据主权感知是最强的信任与口碑资产。
3. 其余 P0/P1 完全一致——核心闭环质量 Q 的权重在 B 中最高，不为增长让路。

## 5. 非功能需求

- **性能**：FR-5 预算表。
- **三态**：所有数据区组件必须设计 loading / empty / error 三态（AGENTS.md §14/§15）。
- **隐私**：不收集个人身份信息；统计埋点（§7）匿名化 + 设置中可关闭；用户数据默认本地/自有存储，不与第三方共享。
- **数据主权**：§4 二分原则执行到 UI（详情页双区）；元数据源可替换（见 02 文档 §5 同步规则）。
- **可访问性基线**：键盘可达（FR-1/P1-8）、色板同时提供文字标签（不只靠颜色）。

## 6. 观察池埋点（两方案共用，服务验证与升级信号）

| 埋点 | 定义 | 驱动的决策 |
|---|---|---|
| 线索覆盖率 | ≥1 根线索的记录占比 | 北极星；"空档案"警报 |
| 搜索失败率 | 无结果搜索会话占比 | 手动建卡是否出观察池 |
| 命名视图创建密度 | 周人均新建数 | Era 官方化 / P1-10 价值 |
| 回响卡片点击率 | 卡片曝光→点击 | Review 触发器有效性 |
| "为什么"回访率 | 详情页个人区回访占比 | 编码价值验证 |
| 导出使用率 | 导出会话占比 | 信任资产；A 方案付费意向代理 |

## 8. 明确不做（铁律）

推荐引擎/相似推荐/Discovery ｜ 社交/关注/评论 ｜ 1–10 评分 ｜ Last.fm 与流媒体自动同步 ｜ gamification 积分打卡 ｜ 统计 Dashboard（用户侧）｜ 地图/地理维度回潮 ｜ 复杂搜索语法 ｜ Tag 层级树 ｜ 智能播放列表 ｜ 多用户/权限/平台化 ｜ 播放器化/试听 ｜ AI 虚构叙事者 ｜ 收听史事件表 ｜ Topster 持久化自由画布 ｜ 用户改写公共元数据（补缺场景红线见 02 文档 §5.3）

## 9. 依赖与风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 音乐元数据源 API 变动/收费/下架 | 元数据与封面获取 | 多源降级链设计（MusicBrainz → Deezer/iTunes Search → Discogs），见 02 §5；本地缓存一切已取数据 |
| 封面缺失/提取失败 | D3 主色缺失 | 降级为"无色板"占位；允许批量回填 |
| 5000 张性能不达标 | FR-5 失败 | 虚拟滚动为硬要求；超预算即阻断发布（预算=验收标准） |

| "那年今日"被感知为打扰 | 支柱四受损 | 四条约束（无推送/单入口/单卡片/确定性锚）+ 可关闭；点击率为观察信号 |
