# A2 体验工程师 · 第二轮最终主张

> 人格参数：发散度 2/5，稳定度 4/5。第一轮立场（round1/A2-robust.md）：三个物理瓶颈——**输入成本、试错循环、扫视成本**，两条量化承诺——一次记录 ≤5 秒、一次模糊找回 ≤3 次筛选 + 10 秒扫视，且在 5000 张与 50 张时一样成立。本轮修订一律以工程与交互可行性为准绳：每条新增/移动的条目必须回答三问——建立在哪个已有概念上、成本是什么、不做是否不可逆。

---

## 1. 吸收（来自谁的什么主张，如何融入）

### 吸收一（本轮对我最重要的修正）：A3 的「接线包」——"听的时期"轴 + Note/Tag 全文检索进 P0

**我第一轮打偏的半格**：我用"Release Year 分组"去承接 5.3 的"2010 年左右"。A3 指出用户心智里的"2010 年左右"经常指**我听的时期**，不是发行年——我把行政时间当成了记忆时间。我的承接建立在一个错误的时间指称上。

**融入方式**：
- P0-3 筛选 chips 增加"我听的时期"一行，与"发行年份"并列，命名写全（"发行年份 / 我听的时期"），绝不缩写、绝不共用控件默认值；
- P0-5 的年份分组提供"发行年份 / 听的年份"两种（同一分组组件渲染两个字段，成本相同）；
- P0-1 搜索框双意图扩展为"一处输入、多字段命中"（标题 / 艺术家 / Tag / Note 片段），这是 A3-P0-2 与 A4-P0-2 的收敛结论，我没有理由独守 P1。

**采纳理由（工程口径）**：两者都是纯查询/索引能力——listenedAt 在 AGENTS.md §4 已存在，Note 的片段匹配在 5000 条规模下是普通 like 查询，零新数据、零新表。而 Note 是全产品唯一"只写不读"的用户字段：写下来却永远找不回，这不是取舍，是缺陷。

### 吸收二：A1 的「可检验口径 + 不可逆防线」——验收三态、Tag 补全提前、档案导出

- **验收口径合并**：我的"≤5 秒 / ≤3 次筛选+10 秒"量化了速度，却漏了可靠性。A1 的"普通记录 ≤3 步/15 秒 + loading/empty/error 三态"补上了这一维——"一次失败的添加比慢 0.5 秒更伤害记录意愿"成立，可靠性就是记录成本本身。两套口径合并为一张验收表（见第 3 节 P0-6）。
- **Tag 自动补全 P1→P0**：A1 的不可逆论证成立——同义分裂的治理成本随存量线性增长，而下拉框成本恒定。折进我的 P0-2 弹层：输入即下拉已有 tag，与"最近使用的 tag chips"并存，两者本来就是同一个输入框的两态。
- **档案导出补进 P1**：我第一轮完全漏掉，而 A1（P1-1）、A4（P1-10）、A5（P1-2）三人独立落到同一结论。作为以防御性思维自居的评审，漏掉"用户资产的保险丝"是我的失职。成本是一个接口一个文件；收益是"敢积累"的前提——我的 P0-5 性能预算和整个"长期积累"承诺都建立在用户敢把 5000 张放进来，而敢放的前提是拿得走。

### 吸收三（低成本顺手采纳）

- **详情页"个人记录区/记忆条"**：A5-P0-4（元数据/个人数据 UI 分区）与 A3-P0-5（第一人称记忆条）本质是同一个信息架构动作，合并为一条 P1，取两者中更简单的形态——视觉分区 + 个人区一行式摘要（"2023 年 8 月记录 · 听的时期：2023 夏 · Tags：夏天/海边 · 当时：青旅的天台"）。零新数据，且它是 Find 的终点（"想起它对我是谁"）最便宜的兑现。
- **"为什么留下它？"**：A5-P0-1 采纳为 P0-2 中 Note 折叠框的 placeholder 文案。措辞零成本，且给 Note 这个低使用率字段一个最轻的播种——我不接受任何强制或打扰形态，但 placeholder 恰好是 A5 自己给出的"可跳过可关闭"的最小实现。
- **listenedAt 语义**：A1-P1-2（默认 = addedAt，可轻量修改）随我 P0-2 的快捷听取时间一并确定，不再单列。

## 2. 反驳（反对谁的什么主张，理由）

### 反驳一：A4 的两条 P0 数据模型变更——「重复记录 = 又听了一次的事件模型」与「手动建卡兜底」

**对"重复 = 收听事件"：**
- 工程上：收听史需要新数据对象（事件表，或计数 + 时间数组）。这是全轮次所有 P0 里唯一改数据模型的条目，直接违反"P0 零新表"纪律。
- 语义上：A4 拒绝 Last.fm 同步的理由是"被动导入把'档案'变成'日志'"——把重复添加事件化，同样把集合变成日志，不能双标。一专辑一记录的集合语义是防噪音底线，A1（P1-4）与我一致。
- A4 说"趁早定数据模型"——这个警觉我接受，但趁早该定的结论是：**Collection Record 对 album 唯一，listenedAt 可更新**。不可逆的决策是唯一性约束，不是事件表。重复路径提供"又听了一次（更新听取时间）"这个转化动作（并入我的 P1-4），成本≈0，覆盖 A4 要的 80%；未来若真需要收听史，append-only 侧表可后加而不破坏集合模型。

**对手动建卡：**
- 并行创建流 + 占位封面 + 日后元数据回填的对账逻辑，是永久性的边角案例制造机；且与 A1 不做清单 #17（本地事实与公共事实的冲突会破坏外部元数据可同步修正的前提）正面相撞。
- 冷门唱片用户是少数场景，代价却是全员承担的永久复杂度。降 P2 观察池，观察信号 = **搜索失败率**；若失败率高，先做的也是"手动建议候选进匹配队列"，仍然不是建卡。

### 反驳二：A5 的 P0-3「Topster 策展语义（副标题 + 自定义顺序）进 P0」

- **它违反 §9 的方式是绕开而不是满足**：自定义顺序 = 持久化排序数组，副标题 = 持久化文本，两者都要求先回答"哪些 Topster 被保存"——这正是 AGENTS.md §9"View 不产生第二套状态"要挡的第二套状态。A1 的 P2-1 为同一理由明确"不做自由画布、不做布局保存"，并指出"保存哪些 Topster"的状态问题必须等 Collection 稳定后裁决。
- **P0 准入纪律**：P0 的标准是"缺则核心承诺失效"。策展语义缺位不伤害 Record/Find 一秒；把它放进 P0 会挤出真正不可逆的条目（Tag 补全、颜色字段、听的时期轴）。P0 不是概念种子池。
- **交互成本**：拖拽排序是网格交互里成本最高的控件之一，与低复杂度目标冲突。
- **让步式替代**：副标题作为**导出时的参数**（填一次、随图走、不落库），同样兑现"表达 + 一句话"，零状态。持久化策展语义留 P2，按 A1 的"每个 View 独立裁决"走。

### 附带降级（非敌意反对）：A3-P0-3 的「结果一律打乱」

再认的关键是候选集足够小——我的实时命中计数已经服务于此；顺序随机不贡献再认，反而破坏确定性扫视，与我的三档密度逻辑（用户按记忆强度选扫视方式）冲突。降 P2：小候选集内提供一个"打乱"按钮即可，不做"一律"。

## 3. 修订后的立场（坚持 / 让步 / 吸收）

### 坚持

1. **三瓶颈框架不变**，且本轮被交叉验证：A1/A3/A4 的 P0 条目几乎全部能映射回三瓶颈——粘贴识别 = 输入成本，chips + 实时计数 = 试错循环，封面墙/色板/密度 = 扫视成本。
2. **P0-3（chips + 实时命中计数）仍是最不可返工的决策**：A3（风险 3）、A4（P0-1）与我三方收敛于同一形态。本轮应当锁定它，表单式筛选不再进入讨论。
3. **P0 零新数据对象纪律**（唯一例外仍是封面主色——它是外部元数据的派生字段，不是新概念）。
4. **优先级纪律：P0 = 缺则核心承诺失效**。本轮我顶住了三处 P0 膨胀（收听事件、手动建卡、策展语义）。
5. **Favorite 熵耗尽预案维持 P2**（Favorite 内拖拽 TopN）；评分继续不做。

### 让步

1. 承认第一轮把"2010 年左右"承接错了半格：时间轴一分为二（发行年份 / 我听的时期），都进 P0 筛选。
2. Note/Tag 全文检索：P1→P0。
3. Tag 自动补全：P1→P0（折进弹层）。
4. 承认漏了档案导出，补 P1。
5. "N 年前的今天"：P2→P1。
6. 详情页个人记录区/记忆条：采纳为 P1。

### 修订版 P0（六条，全部过"零新概念/零新表 + 缺则失效"双检）

1. **记录提速三捷径**（零输入候选 / 粘贴 URL 与"Artist - Album"识别 / 已收藏前置标记）——维持；
2. **Add 弹层扩展件**：Favorite 开关、Tag chips + 已有 tag 自动补全、Note 折叠（placeholder"为什么留下它 / 留一句当时"）、可选快捷听取时间（默认"刚刚"，年份粒度，补记录不使时间线失真）——吸收 A1/A3/A5；
3. **渐进筛选 chips + 实时命中计数**，轴 = Genre / 发行年份 / 我听的时期 / Favorite / Tag / 色板——吸收 A3；
4. **封面主色提取 + 12–16 色板**——维持（记录时顺手算，A4 与我收敛于"数据先行"）；
5. **三档密度 + 年份分组（发行 / 听的两种）+ 5000 张性能预算**——修订分组轴；
6. **验收口径**：记录——理想键盘路径 ≤5s，普通路径 ≤3 步/15s；找回——≤3 次筛选 + 10s 扫视，实时"还剩 N 张"；全路径 loading/empty/error 三态——新增，来自 A1。

## 4. 最终产品主张（200-400 字定稿）

Musicgraphy 2.0 的竞争力不来自新概念，而来自三个物理瓶颈被磨平：**输入成本、试错循环、扫视成本**。

记录端，把"往搜索框里放什么"的成本压到极限——零输入候选、粘贴识别、已有 Tag 点选——让一次普通记录稳定在几秒内完成、失败也不挫败（三态口径）。记录是闭环里唯一不可逆的环节：输入成本不降，用户终会在某次"懒得打字"后停止记录。

找回端，把模糊记忆的试错循环做成一等交互：常驻筛选 chips，每加一个条件立即看到"还剩 N 张"，全程看得见封面；颜色、听的时期、自己写过的话，全部接线为筛选与搜索轴——文档举出的每种记忆（"蓝色的那张""大一那年""我写过的话"）都有一条对应的路。找得回的本质，是不依赖用户当年有预见性。

全部 P0 不引入新数据对象，只做三件事：把既有字段接线、把既有路径提速、给承诺配上可检验的口径与防线（Tag 补全、导出、性能预算）。坚持档案的集合语义：一专辑一记录，重复转化为整理而非事件流。

一句话：**让记录快到用户敢于记录，让找回只需要一根残缺线索——5000 张与 50 张一样成立。**

## 5. 优先级变化

### 升级

| 条目 | 变化 | 理由 |
|---|---|---|
| Note/Tag 全文检索 | P1→P0 | A3/A4 收敛；成本近零；"只写不读"对唯一的自由文本用户字段不可接受 |
| Tag 自动补全 | P1→P0 | 同义分裂不可逆、治理成本随存量增长（A1 论证成立）；实现是一个下拉框 |
| "我听的时期"筛选轴 | 新增 P0 | 纯查询既有字段；修正我第一轮用发行年错承"2010 年左右"的半格偏差 |
| 快捷听取时间（约年份输入） | P2→并入 P0-2 弹层可选字段 | 补记录使 addedAt 时间线失真是第一天就发生的问题（A3-P0-4 的最小形态） |
| 验收口径 + 三态 | 新增 P0 | 质量定义而非功能；来自 A1，与我的量化承诺合并成一张验收表 |
| 详情页个人记录区/记忆条 | 新增 P1 | A3/A5 收敛，取简形；Find 的终点最便宜的兑现 |
| 档案导出 | 新增 P1 | 我的第一轮盲区；三人独立收敛；"敢积累"的保险丝 |
| "N 年前的今天" | P2→P1 | Review 最低成本的触发器（A3-P1-5 / A5-P0-2 收敛，仅一张卡片，无推送） |

### 维持

- P0：记录三捷径、筛选 chips + 实时计数、主色提取 + 色板、三档密度 + 性能预算。
- P1：Tag 合并提示、命名视图（保存筛选组合）、重复→整理转化（扩展一项："又听了一次"= 更新 listenedAt）、键盘流、歌名反查。
- P2：Favorite 拖拽 TopN、色带浏览 View、Topster 导出图片（副标题可作为导出参数）。

### 降级 / 拒绝进 P0

| 条目 | 来源 | 处置 |
|---|---|---|
| 结果内打乱 | A3-P0-3 | 降 P2：小候选集内一个按钮，不做"一律" |
| 重复 = 收听事件模型 | A4-P0-5 | 拒绝数据模型变更；取"重复路径更新 listenedAt"的最小语义 |
| 手动建卡兜底 | A4-P0-6 | 降 P2 观察池，信号 = 搜索失败率 |
| Topster 持久化策展语义 | A5-P0-3 | 拒绝进 P0（第二套状态）；副标题仅作导出参数；持久化策展留待 View 独立裁决 |
| 联想式找回（"同期添加"） | A4-P1-2 | 不入列，P2 观察：便宜，但排在记忆条之后 |

### 不做清单新增

收听史事件表（维持集合语义）；Topster 持久化布局/顺序状态；AI 叙事者（A5 自己的保留意见我完全同意：虚构的记忆是档案的死亡）。
