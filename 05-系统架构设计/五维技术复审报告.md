## 2. P0 发现与处置（V1–V4，实现前必须修）

| 编号 | 发现 | 处置（已落盘） |
|---|---|---|
| V1 | 02-数据模型 §4 停留 v1.0 口径（无 `/api/v1/`、`{data,error}` 双键、无 201/422/鉴权），与 ADR-007 两套 envelope 并存——照旧实现将整体偏离 v1.1 | 02 §4 全节按 ADR-007 重写（端点表 + 错误 envelope + 禁"200+error"歧义形态），02 升版 v1.2；07-ADR 一致性表同步 |

| V4 | 前端渐进增强基线未声明（I3「≤3 步/15s」验收的隐性依赖）；片段替换 <60 行低估（缺竞态防护/回退/错误态/事件委托） | ADR-003/DESIGN DD3 增补**"无 JS 基线"段**：chips=`<a href="?genre=…">`、搜索=原生 GET form、添加=原生 POST+303，JS 岛屿仅做增强（FR-1 粘贴识别/自动补全为纯增强层）；swap 规格化：AbortController + pushState/popstate + 错误片段注入 + document 事件委托，合计 100–200 行 |

| V7 | C2 回退表述自相矛盾：候选表写"Preact SPA + 4 依赖"，正文/F2/DD1 说"回退只换 DAO 一个文件" | 统一为**"仅换驱动，前端与架构其余不变"**；删除 SPA 残留（DESIGN §3 / design.json / ADR-001 失败模式） |
| V8 | ADR-006 缺"运行环境"节：进程守护/TLS/目标 OS/端口/日志/崩溃自愈全未记载；恢复无清单；迁移器缺 journal_mode 事务外注记 | 新增运行环境块：OS 原生守护（**禁 PM2**——自身约 +50MB 会击穿 RSS 预算）、TLS 反代终结或仅绑 127.0.0.1+密钥、部署目标 OS 于 D1 定死、stdout→文件轮转、`uncaughtException` 记日志后 exit(1) 交守护重启；5 步恢复清单 + Node 大版本升级前演练 |
| V9 | 自写 ~80 行 tagged-template html 助手重复造轮子且边界易错（已转义标记/数组 join/Promise 摊平） | 改用 **hono 内置 `hono/html`**（0 新依赖、自动转义 + raw() 逃生口）+ **三条上下文纪律**进代码评审清单：禁 raw() 插用户数据 / 禁 style·script 上下文插值（script 内 JSON.stringify + `<`→`\u003c`）/ URL 插值仅 http(s)·相对路径白名单 |
| V10 | 鉴权仅有结论（"单用户访问密钥"）无规格：cookie/header/未登录页/CSRF 全未定义 | 最小零依赖方案落 ADR-007 条 7 与 02 §4：无 cookie → 302 密钥表单页；`crypto.timingSafeEqual` 比对；HttpOnly+SameSite=Lax+Secure 签名 cookie；CSRF = SameSite=Lax + 校验 Origin/Sec-Fetch-Site（约 10 行）；导出脚本走 `Authorization: Bearer` 备用通道 |
| V11 | cursor 无 tiebreaker 规格（Release Year/Artist/Title 均非唯一键）；`has_next` 放 meta 还是 links 两处口径不一 | cursor = **复合键 `[sort_value, id]` 不透明 base64(JSON) + SQLite row-value 比较**；sort 变更即作废（400 code=cursor_invalid）；`meta.has_next` 放值、`links.next` 放下一页完整 URL；limit 上限 60 |
| V12 | tags 缺唯一约束（R9 只补了普通索引，防不了同名重复插入）；`collection_record.album_id` 未 NOT NULL（SQLite 中 NULL 在 UNIQUE 组合内可重复） | 02 §2.3 补 `UNIQUE(user_id, normalized_name)`；§2.2 album_id 加 **NOT NULL** |
| V13 | RSS 基线 ~45MB 偏乐观（实测 50–120MB）；"告警 150MB"无发出方 | 基线校正（FC6）+ 启动参数 `--max-old-space-size=64`（堆硬上限防失控）；**告警发出方**：进程定时读 `process.memoryUsage().rss` 写日志、越界 WARN，由守护/health 端点承接；<100MB 目标以 D2 实测背书 |
| V14 | "保留 7 份"未定义粒度：一日多次备份会挤掉全部历史 | 按天去重：文件名 `musicgraphy-YYYYMMDD.db`、当日已存在则跳过、**保留最近 7 天** |
| V15 | htmx 升级路径：版本未钉；阈值"岛屿>5"判据错位（混用两套 swap 机制违背硬需求①） | 钉 **2.x 稳定线**；触发条件改"局部刷新形态增多"；**引入即整体替换**自写 swap |
| V16 | dev server 形态未写（无 HMR 的开发体验缺口） | `@hono/vite-dev-server`（devDependency，服务端热更）或最简 `tsx watch` + 手动刷新，写入 DESIGN §8 / ADR-003 |

## 4. 顺手修正（P2 级，因所在段落重写而一并处理，特此披露）

1. 02 §3 那年今日查询两处 bug：`'now'` 为 UTC 使本地"今天"可能偏一天；`added_at` 含时间部分使恰好一周年当天被排除 → 改 `'localtime'` + `date()` 归一。
2. DESIGN envelope"6 条查询全走索引"表述过强 → "索引轴 <1ms、genre 轴经 json_each 不可索引（预期 <10ms）"。
3. 02 §4 `search/albums` 响应补 **`in_collection`** 字段定义（PRD FR-1"候选阶段标注已在 Collection"依赖它）。
