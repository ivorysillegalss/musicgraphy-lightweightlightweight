### 1.2 关键发现：三套字体从未交付——「丑」的第一根因

主线仓全文检索（2026-11-18 实测）：**无任何 `@font-face` / `@import` / 字体文件**——
`src/` 无 woff2/ttf/otf，`dist/static/` 无字体产物，tokens.css 只声明字体栈不加载字体。
MASTER.md 的 Google Fonts `@import` 片段（MASTER.md:82）只是文档参考件，从未落进产品。

后果 = 用户浏览器（Windows zh-CN，100% 缩放）的**实际兑现**：

| 栈 | 声明 | 实际渲染（Windows） |
|---|---|---|
| `--font-body` | Playfair→…→`Inter, 'Noto Sans SC', 'PingFang SC', 'Microsoft YaHei'` | Inter 未装 → PingFang 是 macOS 专有 → **全部落 Microsoft YaHei**（含拉丁字符）。14px YaHei 即 Windows 上经典的「字小发糊」观感 |
| `--font-display` | `'Playfair Display', 'Noto Serif SC', 'Songti SC', serif` | 三者均未装 → generic serif → **中文落 SimSun、拉丁落 Times New Roman**。空态引语、memory-strip `.when`（且配 `italic` = SimSun 合成斜体，**排版禁忌级**） |
| `--font-meta` | `'JetBrains Mono', ui-monospace, Consolas, monospace` | 拉丁=Consolas；**CJK 无一覆盖 → generic monospace 的 CJK 回退 = SimSun**。11px SimSun 大写间距标签 = 全站观感最差处 |

**结论：用户「字体之间的样式都太丑了」的主要成分不是审美选型错，而是设计系统的排版意图在真机上从未发生**。任何「重设计阶梯」若不解决交付层，改的只是纸面值，屏幕上依旧 SimSun + YaHei 混排。这决定了 §③/§④ 的提案重心。

## ② ui-ux-pro-max 方法论重跑记录 + 新 Type Scale 提案（两档供选）

### 2.1 方法论重跑记录（用户点名 skill，流程如实记录）

按 design skill（`_downloads/ui-ux-pro-max-skill/.claude/skills/design/SKILL.md`）路由：tokens/typography 工作 → `design-system` 子 skill（三层 token 架构）+ `ui-ux-pro-max` 主 skill 检索。本次实跑（2026-11-18）：

1. **`--domain typography`**（query: archive collection editorial calm）→ 命中 6 行，与本系统同族者：`Minimalist Monochrome Editorial`（Playfair Display + Source Serif 4 + JetBrains Mono 三栈——正是 MASTER 合成栈的同源行）与 `Bold Typography Mobile`（**其 Notes 给出建议阶梯：12px labels / 16px body / 22px subhead / 32px section / 40px H2 / 56px H1**——「16px body 起步 + 上部大步距」结构）。原选型行 `Classic Elegant`（Playfair + Inter）在档复核一致——**方向结论：三层栈身份（衬线 display + 无衬线 body + mono meta）保留，问题在交付与阶梯值，不在选型**。
2. **`--domain ux`**（query: font size hierarchy readable body text）→ 命中 4 条硬规则：**body ≥16px（mobile）/ 模块化阶梯（示例 12 14 16 18 24 32）/ 一致阶梯禁随意字号 / 4.5:1 对比下限**。Priority 6 表原文「Base 16px, Line-height 1.5」「Text < 12px body = anti-pattern」。
3. **`--design-system` 聚合复跑**（原 dials：variance 3 / motion 3 / density 6）→ 风格行再次命中 Minimalism & Swiss Style（与 MASTER 一致）；typography 行命中 Wellness Calm（Lora+Raleway）——**诚实注记：该工具的 typography 输出是 BM25 配对行检索，query 措辞不同命中行即漂移，它不生成阶梯数字**；阶梯数字必须按其 UX 规则库（上述 16px/模块化）人工构造。故 §2.2/§2.3 的数值 = 按 skill 规则构造、经其优先级表校验的提案，而非工具直出。
4. `design-system` 子 skill 的 token 三层纪律（primitive→semantic→component、validate-tokens 工具在档）= §④ 修订预览的结构依据。

## ③ 字体间「样式关系」重设计

### 3.1 深浅节奏：两阶灰 → 三阶墨

现状只有 foreground（stone-900，对奶油底 ≈13.6:1，MASTER 在档）与 muted-foreground（stone-600，≈6.9:1，MASTER 在档）两档，所有辅助文字挤在后者。提案：

- **一级（正文/标题）**：stone-900 不动；
- **二级（辅助正文/small）**：stone-600 不动（6.9:1 余量充足）；
- **三级（装饰性 mono 标签/overline）**：stone-500（#78716C，**本文计算值 ≈4.2:1**——低于 AA 4.5 常规文字线，**仅限 ≥18px 大字或纯装饰 uppercase 标签**，小字一律留二级；实施期以对比度工具复校后决定是否引入 `--color-tertiary-foreground` token，先进 MASTER 再进代码）。

节奏用法：**同字号换灰阶（small/body 之间）优于同灰阶换字号**——深浅差异在 1.5-2 步字号差内最易感知，这是「深浅节奏」的可操作定义。

### 3.2 字重节奏：400/600/700 三声部 + 禁合成字重

- 现阶梯字重已含 400/500/600/700（meta 用 500）——保留，但补一条**禁合成字重纪律**：CJK 回退字体（YaHei/SimSun）无真 600/700/italic 时浏览器合成加粗/斜体，观感即「丑」。YaHei 有 Bold（可安全 700），**无 Medium（500 合成）**——若自托管 Inter（拉丁）后，中文 500 建议**降级为 400 或 600 二选一**，避免中文侧合成半粗。SimSun 无 Bold——**display 层中文若落 SimSun，禁 700**（§3.3 的根治前提）。
- `.memory-strip .when`（app.css:259）的 `font-style: italic` 在 CJK 上 = 合成斜体，**提案明文禁止 CJK italic**（该落点改为字号/字重对比：17px→display 字体 + 非斜体）。

### 3.3 是否引入第二条 display 字体：**不建议引入新家族；建议「补齐既有 display 的中文半边」**

开放问题（需求草案 R-113）原文即问此。诊断结论：真正的缺口不是「第二个 display 家族」，而是**既有 Playfair Display 从未兑现 + 它的中文搭档从未存在**。三个选项：

| 选项 | 内容 | 代价 | 判断 |
|---|---|---|---|
| α（推荐） | 拉丁侧自托管 Playfair Display（OFL，2-3 个字重 woff2 ≈ 60-120KB）+ 中文 display 走**系统链修复**：`'Noto Serif SC', 'Source Han Serif SC', 'Songti SC', 'SimSun', serif` 显式兜底（SimSun 至少是确定性宋体，大字号下读作「老编辑部」而非随机污染） | 最低；中文 display 质量 = 机器相关 | 快赢；与 B 案同批 |
| β | 中文 display 亦自托管：Noto Serif SC（OFL）unicode-range 切片自托管（盘面 3-8MB/字重，页面实际按需拉 200-600KB 量级——数字为公开常识口径估算，**实施期以实际 vendor 件为准**） | 中（构建资产批 + vendor 脚本） | 中文 display 质量根治；开放问题交用户批 |
| γ | 引入第二 display 家族（如 Newsreader/Lora 等检索行） | 与「档案安静」气质收益不成比例，且多一套交付成本 | **否决建议**——三栈身份保持，零新家族 |

**mono 层 CJK 兜底修复（必做，无论 A/B）**：`--font-meta` 尾部加 `'Microsoft YaHei', monospace`（顺序即语义：拉丁吃 JetBrains Mono/Consolas，CJK 落 YaHei sans 而非 SimSun）——一行改动，消灭全站观感最差层；同族修复 `--font-display` 链（上表 α）与 `.mono` 类改引 `--text-meta` token。

### 3.4 其他样式关系修订（随 A/B 任一案随批）

- **chip/btn/input 行高剥离**：`--text-*` 是 font 简写，body 行高升 1.7 会泄漏进组件（.btn/.input/.chip 均以 `font: var(--text-body)` 引用）——组件层补显式 `line-height:1.2-1.4` 覆盖（app.css 三处级），热区 44px 不变。
- **result-status / wall-end / flash 的层级归位**：这些「半 mono 半 small」的混合层统一归 mono meta 档（B 案 12px），消除 12/13px 野生档。
- **大写+宽字距规则明文化**：uppercase 对中文是 no-op，0.08em tracking 对 11px 中文是灾难；规则 = mono 标签层的 tracking 只服务拉丁，中文标签 tracking ≤0.05em（写入 MASTER Typography 注记）。

## ④ 实施载体建议（T1/T3 分界 + 修订预览）

### 4.1 载体分界：**字号阶梯批 = 纯 T1（零 JS 零 React 零新依赖）**

- 排版是静态呈现属性，React/JS 在「改字号」上**零增量价值**；S2-3 纪律「迁移只服务动效需求」直接适用。用户令「可以充分利用 react 和 js 进行设计」= S2-3 的 **P0 放行令，不是强制令**——诚实结论：本批内 React 的正确落点在**同批其它需求的岛屿**（R-115 入口带 T3 候选、R-117 hover 卡、S2-3 §3 的 A1/A11 入场动效），字体批不需要也不应该引 React。
- 若字体批伴随标题入场类动效（T3 候选 A11 等），动效归 T3/岛屿并按感官层门控；**token 值本身永远 T1**。
- 字体文件交付（若批 §3.3 α/β）= vite 静态资产批（woff2 进 `dist/static/`，OFL LICENSE 随仓），同样不需要 React。

### 4.2 tokens.css 修订预览（文字描述级，不写代码）

1. Typography 段：按 §2.2/§2.3 勾选案替换七档 `--text-*` 值；`--text-meta` 行高 1 → 1.3。
2. 字体栈三行修复（§3.3）：display 链补 SimSun 显式兜底（α 案）或 vendor 名前置（β 案）；meta 链补 `'Microsoft YaHei'` 于 generic monospace 之前；body 链不动（自托管 Inter 后自然兑现）。
3. 若引入三级灰：semantic 段新增 `--color-tertiary-foreground`（先 MASTER 后 tokens，值 = stone-500，带使用边界注记）。
4. reduced-motion 段（tokens.css:94-102）**零触碰**——字号批不进 motion 段。

### 4.3 app.css 修订预览

1. §1.3 全部逃逸字号**收编进阶梯**：9px→meta 档或直接删除该字号（.pop-badge 徽章升 12 或改图标语义）；10px 类→meta 档；11px 类→meta 档（`.mono` 改 `font: var(--text-meta)`）；13px 类→small 档；15/17px→body/h3 档（或新增 `--text-lead` 18px 阅读档，交用户裁）；20/22px→h2/h3 档。
2. 组件行高覆盖三处（chip/btn/input，§3.4）。
3. `.memory-strip .when` 去 italic（§3.2）。

### 4.4 MASTER.md 修订预览（文档批先行——token 唯一来源纪律：先文档后代码）

1. **Typography 节**：新增「字体交付（自托管）」小节——明文**运行时禁 Google Fonts @import**（现 MASTER.md:82 的 @import 片段标记「仅参考、禁入产品代码」），交付形态 = woff2 自托管 + OFL 许可随仓 + CJK unicode-range 切片策略（β 案获批时）；替换 Google Fonts 链接为 vendor 件路径规范。
