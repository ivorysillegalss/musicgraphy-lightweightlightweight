## ① 现状诊断

### 1.1 入口全在页脚：位置与问题

探索类功能的全部 UI 入口都在 `siteFooter()`（`musicgraphy/src/server/html.ts:128-143`）：

- 行 135：「再逛逛你自己的箱子：<a>翻箱</a> · <a>流派星图</a> · <a>收藏全景</a>」
- 行 136：「把品味排成一张图：<a>Topster 是什么</a> · <a>我的策展</a>」

问题三点：

1. **可发现性**：页脚是视觉动线的终点。主页（Collection）自页头以下到墙底前的全部信息块
   （§1.2）没有任何探索类入口——用户不滚到底部就不知道 /genres /topsters /crate /panorama
   存在。这与 S2-1 交付时的普查结论同构（2026-11-15 普查：/topsters 系列四页 0 处 UI 入口），
   R-115 = 同一缺口从「页脚补行」升级为「顶部建带」。
2. **动线错位**：探索类页面是「看档案的另一种方式」（Review/Discover 轴），天然应该在
   用户 *看着自己的墙* 时被看见——墙与入口隔了一整屏信息块，动线断裂。
3. **页脚纯出口语义不可破坏**：页脚同时承载数据主权行（导出 JSON/CSV/zip）、观察池仪表、
   登录态行（S2-29）、赞助插座（W11）——这些是「出口/主权」语义，R-115 方向明文
   「页脚保留纯出口（数据主权）语义不破坏」。**升入口带 ≠ 删页脚行**（页脚两行探索入口的
   去留见 §6 开放问题 9，本文建议保留）。

## ② 入口带方案提案（两档供选 + 位置与动效概念）

### 2.0 位置候选（先于形态裁决）

| 位 | 位置 | 论据 | 代价 |
|---|---|---|---|
| **A（推荐）** | 页头正下、回响卡上（renderCollection body 第 1 块） | 「放到最上面去」原文最直译；导航级语义最明确；不与回响卡抢注意力（回响卡降为第二叙事块） | 首屏预算代价最大（§③） |
| B | 回响卡下、SAVED VIEWS 上 | 回响卡（命中日）保留「第一眼惊喜」位；入口带与视图/舱同属「工具带」 | 条件块漂移：无回响日入口带跳到顶部，位置不稳定 |
| C | 筛选舱上方、SAVED VIEWS 下 | 与「工具区」聚合；墙最近 | 「放到最上面」语义弱；对非探索动线帮助最小 |

**sticky 注记**：入口带**不建议**进 sticky 区（site-header 已 sticky 占 78px；带若跟随滚动
常驻视口，每屏永久扣 ~60-190px，与 §③ 预算冲突）。普通文档流块，滚走即让位。

### 2.1 方案甲 · 探索卡组（Explore Cards）——趣味浓度高

每功能一张迷你卡（≈176×136px，6 张一行塞满 1128px 舱宽）：微缩视觉（72px 高）+ 功能名
（--text-body 600）+ 一句第一人称档案馆口吻文案（--text-small，沿用 S2-16 口径如
「再逛逛你的箱子」）。整卡 = 一个 `<a href>`（DD3 纯链接）。

**每入口趣味动效概念**（全部键在 `body[data-sensory="on"]` 门控下，缺省安静；
hover 触发为主，理由见 §5 反模式核对）：

| 入口 | 微缩视觉（SSR 静态） | 趣味动效（hover） | 分级 |
|---|---|---|---|
| 流派星图 | 5-8 个真实 top 流派名散点排布（字号错落，黑/琥珀双色） | 节点间距微张（transform 1-2px）+ 1-2 个节点琥珀闪烁（opacity 0.6→1，--dur-slow 交替）——「共现点亮」预览 | **T1 可达**（keyframes）；T3 增益 = 逐节点 stagger 入场 + 指针跟随连线 |
| Topster | 3×3 微缩网格：3 张真实封面 + 6 主色灰格 | 逐格落位 stagger（translateY 4px→0 + opacity，animation-delay 30ms×n）——「网格正在排」 | **T1 可达**；T3 增益 = FLIP（未来拖拽重排预览才需要） |
| 翻箱 | 4-5 条真实封面窄裁侧脊横排（spine 同款） | 整排 translateX(-8px) + 最前脊 rotateY 6deg 微抽出——「翻找感」 | **T1 可达**（既有 .spine transition 同族，app.css:372）；T3 无必要 |
| 收藏全景 | 6-10 个主色圆点簇（取真实 --swatch 分布模拟 decade×genre 簇） | 簇间距缓移 3-4px（transform 循环，模拟聚类漂移）+ 中心点放大出微缩封面 | **T1 可达**（transform 缓动）；T3 = canvas 微缩版（⚠️ 不迁移 panorama-view，独立微实现，见 §4） |
| 专辑地图（存疑入口） | 地球弧线静态 SVG（1 条经线 + 2-3 色块） | 经线描边扫过（stroke-dashoffset 动画） | **T1 可达**；R-116 落地前视觉语义薄（§1.3） |
| 随机一张 | 单张微缩封面 + shuffle 图标 | 封面 rotateY 翻面露出「?」背面（CSS 3D，--dur-slow） | **T1 可达**；T3 = 连续抽卡流（= 评审案 A17 同源，随 React 波次另裁） |

**诚实标注**：微缩视觉若用真实数据（真实流派名/真实封面），SSR 直出零新增查询（§4.3）；
若全静态装饰（假流派名/灰格），T1 成本最低但「趣味」降为「贴图感」。**建议真实数据版**
——数据全在本地档案，取数纪律与 LIMIT 无冲突。

### 2.2 方案乙 · 胶囊导航行（Explore Pills）——预算最省

页头下一行胶囊（图标 + 功能名，min-height 44px 热区，flex-wrap 禁裁切——MASTER chip 规则
同款）：`星图 · Topster · 翻箱 · 全景（· 地图 · 随机）`。总高 ≈ 44-52px + margin 16 ≈ **60-68px**。

动效：hover 时**胶囊内图标做各功能专属微动**——星图图标内两点交替闪烁、Topster 图标三格
依次升起、翻箱图标侧脊滑出一线、全景图标色点漂移——全部为 Lucide SVG 内联 + CSS
（stroke-dashoffset / opacity / transform），**T1 全覆盖，T3 无必要**（React 在乙方案里没有
可达成的增量价值——诚实结论：乙不需要岛屿）。

## ③ 首屏高度预算核算（与 R-113 新字体 / R-114 减量联动）

**测量基准**：main 内容宽 1176px（≥1308px 窗口）；1080p 100% 缩放可视高 ≈ 940px；
1440×900 笔记本 ≈ 790px。墙 = `minmax(148px,1fr)` 7 列 × 154px，行距 170px（app.css:147）。

### 3.1 现状堆叠推算（静态估算，实施期实测复校）

| 块 | 现值估算 px | R-113 后（正文 14→16 等，+10~18%） | 条件性 |
|---|---|---|---|
| site-header（sticky 常驻） | 78 | ≈ 88 | 恒 |
| main padding-top | 48 | 48 | 恒 |
| 回响卡 + margin | 88+24=112 | ≈ 122 | 命中日才有 |
| SAVED VIEWS 行 + margin | 44+24=68 | ≈ 78 | views 非 null |
| TAG GOVERNANCE + margin | ≈ 80 | ≈ 90 | 当季有候选 |
| 筛选舱（padding 48 + 轴块 wrap） | 300-380 | 340-440 | 恒（Genre 恒展开 18 项 = 主因子） |
| 结果状态行 | ≈ 44 | ≈ 48 | 恒 |
| **合计到墙顶** | **≈ 620-750**（两条件块皆无）/ **≈ 815-955**（皆有） | 上表 +60~90 | — |

推读：现状在 1080p（940px）上**墙第 1 行勉强可见、第 2 行不可见**；1440×900 笔记本上
第 1 行已切顶。R-113 放大后全面恶化 60-90px——**这正是 R-114（舱减量）存在的理由，
也是 R-115 预算核算必须三案联算的原因**。

### 3.2 加入入口带后的三案联算（1080p = 940px 基准）

| 情景 | 到墙顶估算 | 首屏可见墙 |
|---|---|---|
| 现状（条件块无）+ R-113 | ≈ 680-840 | 第 1 行（部分情景切顶） |
| **乙（+65）** + R-113 | ≈ 745-905 | 第 1 行（贴线）——**乙可独立交付** |
| 乙 + R-113 + R-114（舱 -80~180） | ≈ 590-780 | 第 1 行全 + 第 2 行大部 |
| **甲（+190）** + R-113 | ≈ 870-1030 | 第 1 行切顶/不可见——**甲不联动 R-114 = 不可交付** |
| 甲 + R-113 + R-114 | ≈ 700-890 | 第 1 行全（或近全） |

**结论（诚实版）**：甲方案「有趣的入口」与 cover-first 形态铁律直接争首屏——甲**必须**
与 R-114 同批或排后交付，且卡高预算锁死（≤148px）；乙方案可独立先行、零风险。
若用户对「趣味」权重高（本批 R-118 展示质量条款的精神），建议**乙先行 + 甲随 R-114
同批评估**的序列，而非一步到位甲。

**移动端（375px）**：墙 2 列 × ≈151px；甲在移动端应转横向滚动 snap 条（高 ≈ 120px），
乙两行 wrap 或横向滚动（≈ 96px）——形态细节随实施批 ui-ux-pro-max 复审定（R-118 门）。

## ④ 实现影响面（T1 版与 T3 版分开列）

### 4.1 服务端（两案共同）

- **`html.ts`**：新增跨页共享呈现件（放 siteHeader/siteFooter 之间区段，本文件头注释
  「跨页面共享的呈现件」口径内）——甲 `exploreBand(...)` / 乙 `explorePills()`。
  **layout() 是否直接内挂**两案：内挂 = 12 页全部获得入口带（一致导航，但 detail/add 等
  任务页出现导航带是否有害须评审）；由 `renderCollection` 组装 = 仅主页，最小影响面。
  **建议**：呈现件放 html.ts、**组装权在各页**（collection.ts 先接，其余页待用户批）。
- **`pages/collection.ts`**：renderCollection body 插一行（位置按 §2.0 勾选结果）。
- **`routes/pages.ts`**（仅甲的数据驱动版）：SSR 直出预览 props——top 流派名 = 现有
  `countAxes` 的 genre facets 前 5-8 项（零新增 SQL）；翻箱/Topster 微缩封面 = **复用
  items[0..3]（墙首批已在内存）零新增查询**，或 `listPage({limit:4})` 一条轻查询
  （LIMIT ≤60 纪律余量充足）。不新建端点（T1/SSR 版）；若二期改岛内取数才议
  `/fragment/explore-preview`（届时另评）。

### 4.2 客户端 / React 岛屿边界（S2-3 候选 A 框架内）

- **T1 版（甲的静态视觉 + CSS 动效 / 乙全部）**：**零岛屿、零 JS 增量**。main.js 2,847B
  不动；main.css 增量预估 1-2KB（keyframes + 卡样式，软提醒线 2KB 内贴线，随 evidence
  报告——评审案 §5.3 口径）。
- **T3 版（甲二期：数据驱动微缩 + stagger/FLIP）**：**新建探索入口岛**
  `explore-band`（`src/client/islands/explore-band.tsx`），`main.ts` ISLANDS 注册表 +1 行，
  对外导出 `mount(root)`（内部 createRoot——评审案 §4.3.3 契约）；SSR `<a>` 结构保留、
  岛屿仅增强视觉层（React render 的也必须是真 `<a>`，见 §5 乙-1）。**既有 10 岛零改动**；
  panorama-view/globe-view 维持原生豁免单不受影响（全景微缩视觉是独立微实现，非其扩展）。
  React 共享 chunk 懒加载不进首屏（评审案 §4.3.2 同构论证）。
- **tsconfig/eslint**：T3 版两行级（jsx: react-jsx + include *.tsx）——随 React 基座 P1 批，
  不由本卡独立承担。

### 4.3 DD3（URL 即状态）核对

- 全部入口 = 纯 `<a href>` 指向**既有**路由：`/genres` `/topsters`（建议直连列表页而非
  about 页，见 §6-3）`/crate` `/panorama` `/atlas` `/random`——**零新 query 参数、零新路由**。
- `/random` = GET 302 既有动作（routes/pages.ts:666），纯链接语义成立。
- 键盘可达：卡/胶囊即链接，Tab 顺序自然；focus-visible 用既有 --color-ring。
- aria-label 用完整短句（如「打开流派星图——你的流派宇宙」），不用裸图标。
