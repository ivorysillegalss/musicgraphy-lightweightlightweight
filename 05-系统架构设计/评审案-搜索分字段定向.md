## 1. 结论（方案 b 定稿）

**q 参数值内前缀语法：`artist:` `title:` `tag:` `note:`（空白分隔记号；前缀名大小写不敏感）。
多前缀 = AND 组合；无前缀文本段维持现状盲搜（四字段 OR）；整串无任何已识别前缀 =
与现状完全一致（向后兼容零行为变化）；未知前缀 = 字面量参与盲搜；空值前缀忽略。**

- 例：`artist:キリンジ title:三` = 艺术家含「キリンジ」**且**专辑名含「三」；
  `artist:"Jordan Rakei"` = 引号值支持含空格（无引号值 = 到下一个已识别前缀记号或串尾，
  贪尾语义——裸文本须置于前缀之前或加引号）。
- 记号以空白为界：`artists:x` 不识别（前缀后多字符 = 字面量）；`artist:"x"title:y`
  引号后无空白紧邻部分按字面量归盲搜。
- 外部链（`/api/v1/search/albums` 与 search-suggest 外部组）解析**同一语法**，逐源映射
  （§4）或诚实降级（§5）；tag/note 为本地概念，其值折入盲搜文本不丢词。

## 2. Q1 · DD3 零新参数论证（为什么不加 `artist=` 独立参数）

- **URL 即状态saved-views 三处联动**：独立参数需改 parseFilters / buildHref / saved-views
  序列化三处 + 全部已有分享链接失效；q 值内语法 = 一处解析全链生效（SSR 页面、
  `/api/v1/collection`、`/api/v1/records`、search-suggest 片段同走 buildWhere）。
- **R-105 先例锚**：年份区间（year_from/year_to）因破 DD3 被否决改原生 details 收纳——
  同一裁决逻辑反用于本方案：把表达能力放进既有 q 值而非新参数。
- **防抖候选过滤零改动**：search-box 岛屿、/fragment/search-suggest 接口签名不变。
- 冒烟实证：`GET /api/v1/collection?q=artist%3ATrain` 请求只携带 `q` 一个参数、
  200 + 结果正确（tests/search-fields.smoke.test.ts「URL 即状态零新参数」例）。

## 3. Q2 · P1 本地实现落点（一处接线全链生效）

- **解析器** = `src/server/db/search-parse.ts`（纯函数零依赖，任何输入不抛错）：
  输出 `{ bare, artist, title, tag, note, fielded }`；转义不在本层（escapeLike 由消费方施加）。
- **buildWhere 接线**（`src/server/db/sql.ts`）：前缀值逐条 LIKE 条件（artist→m.artist /
  title→m.title / tag→EXISTS tags（t2.name，与现状盲搜同轴）/ note→r.note；均 LIKE ESCAPE
  prepared 参数化）；bare 段维持现状四字段 OR。**无前缀时生成 SQL 与旧实现字节同形**
  （测试断言全等字符串），全链调用方（dao.listPage 两处 = 列表与 facet 计数）自动生效。
- **S2-3 归属尊重**：islands 仅动 search-box.ts 提示文案一行（focus 空态文案追加
  「支持定向：artist: / title: / tag: / note:（例 artist:"Jordan Rakei"）」）；placeholder
  属性在 pages 层（不在本卡边界）不动。

## 5. Q4 · 降级口径（诚实原则）

1. **源级降级**：源不理解分字段语法（Deezer 全量；iTunes 组合/多值/含 extra；Discogs
   多值）→ `blindQueryOf(fields)` = 全部值以空格连接（前缀记号与引号剥离，保留用户原词）
   ——比传字面量 `artist:foo`（会被当普通文本搜）更接近用户原意，且为空防线 `|| q`。
2. **链级兜底**：MB CJK 字段短语 0 命中 = 合法空响应 → SourceChain 自动降级下一源
   （本环境 Deezer 不可达 → iTunes 折叠盲搜接手；CJK 单字段 artist: 在 iTunes 走
   artistTerm 字段化命中）。**空结果不是错误，是降级信号**——与既有链语义一致。
3. **本地语义**：空值前缀（`artist:` 单独）→ 无条件 = 全量（q 视为空）；未知前缀字面量
   参与盲搜（不报错不吞词）。

## 6. Q5 · FTS5 全文索引（后置观察项，本批不实施）

- 现状性能锚：5000 行四字段 LIKE 1–2ms（tests/perf-like.test.ts 保持全绿）；
  分字段不改变 LIKE 形态（仍 `%v%` 逐字段），无新增全表扫描路径。
- 前缀语法不依赖分词——FTS5（tokenize/中文分词/加权排序）是**相关性优化**课题，
  与本卡「定向过滤」正交；若未来记录量级或相关性诉求上来，FTS5 作为独立评审案
  （涉及迁移 + schema 变更）再议。本批零迁移零 schema 变更。
