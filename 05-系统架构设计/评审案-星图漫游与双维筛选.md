## 1. 结论与推荐（待用户裁决）

1. **载体：推荐案 A = 独立「漫游」载体（用户口径的「星图界面」内改造），案 B（复用 /atlas
   地图作地理入口）排除为漫游主载体**——理由链 §3.3。案 A 内部子形态二选一：
   **A-1 = /genres 页内增「漫游舱」区块（推荐）** vs A-2 = 新路由 /roam（零触碰既有页），
   路由级裁决留 §8 待裁决清单第 2 项。
2. **双维值域**：时间维度 = **年代档 1950s~2020s 八档**（release_year 全量覆盖实测，§2.4）；
   地区维度 = **country 已知值直选 chips（数据驱动生成，只渲染 count>0 的值，附命中数徽标）**，
   诚实标注覆盖率（0% 实测 / ≈2.0% B10 历史口径）→ 地区维度一期定位为
   **「诚实的小维度」**：不硬编码国家清单、不做大洲归组映射表（§4.2），厚度增长依赖
   B10/R-111 权威化管线延续。
3. **随机机制：推荐「seed 入 URL 的确定性取样」**（count + OFFSET 单行取样，成本与
   `ORDER BY RANDOM()` 同量级）——筛选与 seed 全部入链可分享可回放（乙-1 加分项）；
   「再抽一张」= 服务端烘焙新 seed 的纯 `<a>` 链接，后退 = 上一张卡，**漫游核心闭环零 JS**。
4. **交叉空态：推荐 R2 = 自动放宽 + 结果卡上明示**（该组合 0 命中 → 先放地区 → 再放年代 →
   全部档案），R3（空态页 + 手动放宽按钮）作备选（§4.3）。
5. **「介绍」卡片 = 现有字段组装**（DETAIL_COLS + SQL_RECORD_TAGS 同款查询，零新 schema
   零新数据）：封面 + 标题/艺术家/发行年 + 产地徽标 + Genres chips + Tags + note（个人线索）
   + Favorite/added_at/listened_at + 详情链接；预览按钮（同源代理流式）为可选项。
6. **实现影响面**：迁移零、schema 零、（T1/T2 路线下）新依赖零；DAO 增量 = 随机取样 +
   两轴计数共 2–3 个方法（randomRecordId 先例直系扩展）；React 岛屿 = 可选增强层
   （S2-3 P1 基座落地后 T3 承载揭示动效，不阻塞核心交付）。

### 3.3 排除案 B 的理由链（汇总）

① **数据覆盖不适配**：country 是全库最薄字段（0%/2.0%），而案 B 的全部价值恰恰押注在
「地理面点击」上——98% 国家近隐身（empty 态 opacity 0.06 是 DR-M3 诚实呈现的正确设计，
但对「筛选器」是失效形态）；案 A 的 chips 机制天然只呈现命中值，稀疏可诚实。
② **前置工程错位**：/atlas 真实数据接线（availability API + iso 键映射资产）是 R-106 轨道
的既定工作，本就未开工；为漫游先铺这条线 = 把两个需求的依赖链焊死，违反「不为单次需求
顺带重构无关模块」。
③ **重量错配**：随机抽卡 = 毫秒级 SQL + 一张卡的 DOM；maplibre 1.08MB chunk 与 WebGL
对「随机渲染一张专辑」零增益。
④ **DD3 复杂度**：地图相机态/选中态/主题态已占 /atlas 的 URL 命名空间，再叠 seed 与
浮层态会让一个页面承载两套状态机。
⑤ **语义保护**：R-106 = 「专辑集合作为可漫游场所」的空间叙事（封面为展品的 WebGL 画布），
与本需求的「随机抽卡漫游」是两种体验；案 A 让 /atlas 继续专注 R-106。
**案 B 的合法残值**：未来 /atlas 接真数据后，漫游舱可放一枚「在 Atlas 上看产地分布」

## 4. 双维筛选设计

### 4.1 时间维度：年代档（健康维度）

- **语义** = 专辑**发行年代**（`album_metadata.release_year`），非听期——`listened_at`
  语义错位（那是「我何时听的」个人事实，且 precision 仅 'year' 档、覆盖 71.4%，作漫游
  时间轴会把「1950s 的专辑」筛成「2024 年听的专辑」），不加此轴。
- **值域提案**：八档 `1950s…2020s`（实测全非空，§2.4）；URL 参数 `decade=1980`
  （档起点年，SQL = `m.release_year BETWEEN ? AND ?+9`，等价 `release_year/10*10` 分桶）。
  档位不硬编码——服务端按 `GROUP BY release_year/10*10` 数据驱动生成 chips（未来出现
  1940s 或 2030s 自动出现/消失，零维护）。
- **「不限时间」缺省档**：不选 = 全时间随机；八档 chips 并列直选。

### 4.2 地区维度：country 已知值直选（诚实的小维度）

- **值域提案 = 国家直选，数据驱动**：chips 由 `SELECT m.country, COUNT(*) … WHERE
  TRIM(country)<>'' GROUP BY country ORDER BY count DESC` 生成，**只渲染 count>0 的值**，
  每枚附命中数徽标（`日本 · 12` 形态）。原值直出直编 URL（`encodeURIComponent`），
  **不硬编码国家清单、不建 country→大洲映射表**——覆盖率 0–2% 的现实下，大洲归组
  只是给 5–20 行数据套一层粗桶，交叉年代档后大概率整行空态，反而制造更多空转路径；
  且映射资产 = 新维护面（归组口径争议 + 长尾国家归属）。
- **降级口径三态**（诚实标注，缺数据不装有数据）：
  1. **count>0 的国家存在** → 该国家成 chip（当前本环境 = 无任何 chip）；
  2. **country 全空** → 地区维度退化为单档「不限地区」+ 一行 muted 文案：
     「产地档案还在补全中（MusicBrainz 权威化管线）——先用年代抽一张」（诚实，且给
     管线存在感）；
  3. **部分补全** → chips + 页首覆盖率注记：「已知产地 105 张 · 占全库 2%」（数字来自
     同一聚合查询，随库自更新）。
- **覆盖增长路径**（登记依赖，非本期范围）：B10 剩余 ≈67 行增量重跑（blocked 中，待
  用户裁决 DB 搬运）+ R-111 多源权威化（主案候选①字段级多源回退）——地区维度随管线
  自动变厚（chips 数据驱动即为此设计）。

### 4.3 交叉空态处理（须评审的放宽规则）

country × 年代 的交叉矩阵 = 已知国家（≤105 行）× 八档——**空格是常态而非异常**。
提案两案：

| 案 | 规则 | 取舍 |
|---|---|---|
| **R2 自动放宽 + 明示（推荐）** | 组合 0 命中时按确定性顺序放宽：**先放地区（保年代档）→ 若仍 0 再放年代（保地区）→ 若仍 0 回退全库**；放宽动作在结果卡顶部明示（如「1980s×巴西 暂无命中——已放宽为 仅 1980s」） | ✅ 漫游 = 低认知负荷探索（playful 原则），零额外点击；放宽透明不静默 |
| R3 空态页 + 手动放宽 | 0 命中渲染空态卡（文案 + 「放宽地区」「放宽年代」两枚按钮） | 筛选语义最严格，但漫游节奏多一次点击 |

推荐 R2：放宽链**确定性**（固定顺序、同输入同结果），与 seed 回放兼容（§5.1）；
放宽发生的层级记入 URL（如放宽后 `country` 参数保持原值并追加 `loosen=country`），
**分享链接复现同一放宽结果**——不破坏乙-1。

### 4.4 命中数预告知

筛选舱内每枚 chip 附命中数；双维组合的命中数在点击前可见（组合计数条或选中区
预览行）——「点之前就知道有没有货」是稀疏维度必备的诚实交互。

## 5. 随机渲染机制

### 5.1 随机 SQL 口径（三候选）

| 候选 | 口径 | 可分享/回放 | 成本 | 判定 |
|---|---|---|---|---|
| a | `… WHERE <筛选> ORDER BY RANDOM() LIMIT 1`（randomRecordId 先例直系扩展） | ❌ 每次新鲜 | 全量行排序取样，5k 行 ms 级 | 兜底保留 |
| **b（推荐）** | **确定性种子**：`SELECT COUNT(*) WHERE <筛选>`（聚合 1 行）→ `SELECT … LIMIT 1 OFFSET :seed % count`（单行） | ✅ 同 seed 同结果（数据快照期内） | count 聚合 + offset 扫描，5k 行 ms 级（LIKE 5000 行 1–2ms 先例同量级） | **主案** |
| c | 取 id 全列 JS 侧取样 | ✅ | 读 5k 行——**违乙-10 LIMIT≤60 行读取纪律**（聚合豁免口径不适用于取行） | 排除 |

- **seed 语义**：`seed` = 非负整数（服务端生成，0..2^31）。URL **带 seed = 回放态**
  （确定性取 offset=seed%count 那一行）；**不带 seed = 新鲜抽**——服务端随机生成 seed
  后 **302 重定向到规范 URL** `/genres?country=…&decade=…&seed=N`（与 /random 302 先例
  同构，浏览器历史条目落规范地址）。
- **诚实边界**：seed 的确定性 = **数据快照期内**——库增删后同 seed 可能命中不同行
  （offset 基变了）。这不是缺陷而是可接受语义（分享链接保「当时抽到的那张」到库变更为止；
  真要永久保结果 = 存漫游历史表，属新功能不在本期）。
- **加权随机**：一期**均匀随机**（纯随机）。加权（favorite 优先/未听过优先）列为后续
  可选项——加权会让「seed 回放」需要权重快照，复杂度跳档，一期不背（登记观察）。

### 5.2 「专辑 + 介绍」卡片内容构成（零新数据）

| 区块 | 来源字段 | 查询 |
|---|---|---|
| 封面 | `cover_local`（本地文件）/`cover_url` 兜底占位 | 同源 `/covers` 流式（封面懒下载钩子既有） |
| 标题/艺术家/发行年 | `m.title` `m.artist` `m.release_year` | `SQL_DETAIL` 同款（DETAIL_COLS，sql.ts） |
| 产地徽标 | `m.country`（非空才渲染） | 同上 |
| Genres chips | `m.genres`（JSON 数组） | 同上（json_each 口径与星图节点一致） |
| Tags | `tags.name` | `SQL_RECORD_TAGS`（sql.ts:12 既有） |
| 个人线索（「介绍」主体） | `r.note` 非空段 + `r.listened_at`（precision=year 时只显年份）+ `added_at`（收藏于） | 同上 |
| ♥ Favorite | `r.is_favorite` | 同上 |
| 动作行 | 「查看详情」→ `/album/:id`；「再抽一张」→ 新 seed 链接；可选「试听」→ `/album/:id/preview`（同源代理，S2-27 先例） | — |

「介绍」= 上述**现有字段的组装**（外部元数据 + 用户线索），**零 credits**——词曲制作人
属 R-117 数据缺口（schema 无此字段），两阶段路径归 R-117 评审，本卡不重复立项。
全部字段经 hono/html tagged-template 转义直出（乙-6；禁 raw 插用户数据）。

### 5.3 交互与 DD3 闭环（漫游核心零 JS）

1. 筛选 = chips `<a>`（`?country=&decade=` 替换、seed 置新）+ 「抽一张」= GET 表单或
   纯链接——SSR 直出结果卡，**无 JS 全程可用**（S2-25 同构哲学，产品兜底承诺口径见
   S2-3 评审案附录 B）。
2. 「再抽一张」= 服务端渲染时烘焙**新 seed** 的 `<a href="/genres?…&seed=<next>">`——
   点击 = 导航到新结果；**后退 = 上一张卡**（每张卡一个历史条目，天然时间线）。
3. React 岛屿 = **可选增强层**（不承载核心路径）：卡片揭示动效（翻转/淡入，T1 CSS 或
   T3 React 岛屿 `roam-card`）、双维筛选的即时组合计数预览（T2/T3）。S2-3 P1 基座
   （react/react-dom）落地后 T3 可用；基座未落地前 T1/T2 路线零依赖可先行——**动效
   全部键在 `body[data-sensory="on"]` 门控下（缺省安静）**。
