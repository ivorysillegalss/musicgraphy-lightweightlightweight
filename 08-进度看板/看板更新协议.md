# Musicgraphy 2.0 · 进度看板更新协议

> **用户强制约束（2026-11-12）**：在本工作区做的任何工作，完成之后必须立即按本协议
> 同步看板——未同步看板 = 未完成交付，对所有 agent 无例外。看板与代码不一致时，
> **以代码为事实源**修正看板（evidence 注明复核日期）。
> 性质：自迭代运维模块的约束文件。所有在本项目上工作的 agent（主会话或子 agent）
> 在实现任何卡片对应工作后，**必须立即按本协议更新看板**——这是交付定义的一部分，
> 未更新看板 = 未完成交付。
> 看板位置：`08-进度看板/index.html`（双击可开，无需服务）。

## 1. 事实源与角色分工

| 文件 | 角色 | 谁能动 |
|---|---|---|
| `progress-data.js` | **唯一进度数据源**（卡片内容全部来自这里） | agent 按本协议更新 |
| `index.html` | 展示壳（样式与安全姿态固定） | 禁改 |
| `app.js` | 渲染器（2026-11-14 用户裁决改为主线视图，见文件头注） | 展现形式变更须用户裁决后改并登记本协议；进度数据仍只写入 `progress-data.js` |
| `看板更新协议.md` | 本协议 | 仅用户裁决变更时改 |

## 2. 何时更新（触发时机）

1. **开工时**：把对应卡片 `status` 置 `in_progress`，写 `desc`（要做什么）。
2. **实现完成后立即**：`status: 'done'`，并**必须同时**更新：
   - `evidence`：可核查的证据——命令与结果数字、测试计数、commit hash、文件路径、实测值（RSS/耗时/行数）。禁止"已完成"三字空证据。
   - `updated`：当天日期（YYYY-MM-DD）。
3. **受阻时**：`status: 'blocked'`，`evidence` 写明阻塞原因与所需裁决。
4. **置 done 的前置条件**：`npm run check` 全绿（tsc / eslint / vite build / test）——
   门禁不过不得置 done（护栏卡 G4）。
5. 周末门禁类卡片（如 W1-6）由当周收口会话更新。
6. **git 提交（2026-11-14 用户新原则）**：所有卡片修改完毕（建卡/状态流转/evidence 更新均含）后**必须 git 提交**——文档包 = git 仓（2026-11-14 新建，分支 `main`，基线 a0a4012，提交身份 `agent@musicgraphy.local`）；**卡片未提交 = 未完成交付**（与「未同步看板 = 未交付」同级）。

## 3. 怎么改（操作规范）

> 2026-11-14 修订（用户裁决）：看板展现由周阶段（phases）改为主线视图（tracks——设计/数据爬取/后端/前端/集成发布/运维护栏），卡片串行列举并以 deps/relations 显式表达依赖。该次整文件重写属裁决特例；日常更新仍遵守小步 Edit 与下述规范（新结构下对应字段仍为 `status / desc / evidence / updated`，`deps/note/origin` 由裁决性改版维护）。

- 只编辑 `progress-data.js` 中**自己负责的那张卡片对象**的 `status / desc / evidence / updated` 四个字段；不新增删除卡片，不改他人卡片，不动 `meta`（`lastSync` 由每次全量同步的会话更新）。
- 新增任务卡：只能加进对应 `phase.tasks`，id 顺延（如 W1-7），并在 `evidence` 注明来源（哪份文档/裁决新增）。
- **并行保护**：本项目实测存在并行会话交叉编辑——编辑前必须重读文件最新内容，小步 Edit，不做整文件重写。
- 语法自检（提交/收口前跑一次）：
  ```bash
  node -e "global.window={};require('./08-进度看板/progress-data.js');var d=window.MG_PROGRESS;console.log('tracks='+d.tracks.length, 'relations='+d.relations.length, 'ok')"
  ```
  输出 ok 才算有效更新。
- 更新后用浏览器打开 `index.html` 目检一次对应卡片（或让用户查看）。
- **git 提交纪律（2026-11-14 用户新原则）**：卡片/文档修改完毕 → 文档包内 git 提交（仓库级身份参数 `git -c user.name="workspace-ops" -c user.email="agent@musicgraphy.local" commit`，message 带卡片号；只 add 本次变更文件，禁止 `git add -A` 带入他人会话文件）。收口四步 = 语法自检 → git 提交 → zip 重建 → 线上重部署。

## 4. 状态取值

| 值 | 语义 |
|---|---|
| `done` | 实现 + 门禁全绿 + 有可核查证据 |
| `in_progress` | 已开工未收口（在制品未提交也要如实标注在 evidence） |
| `pending` | 未开工 |
| `blocked` | 受阻待裁决/待外部条件 |
| `watch` | 工程护栏持续观察卡（不参与进度计数） |

## 5. 禁止事项

- 禁止无证据置 done；禁止跳过 npm run check。
- 禁止修改 `index.html` / `app.js` 来"改进度"——进度只存在于数据文件。（2026-11-14 修订：展现形式变更经用户裁决可改 `app.js` 并在本协议登记；进度数据仍只写入 `progress-data.js`，`index.html` 展示壳未动）
- 禁止删改历史卡片编号与已冻结的证据记录；纠错时更新 `evidence` 并注明修正日期。
- 禁止在本文件与看板里引入外部网络资源（保持零请求、零注入面的安全姿态）。

## 6. 同步导出

文档包有对外同步产物：工作区根目录 `Musicgraphy-2.0-文档包.zip`；对外版本控制：文档包 git 仓（2026-11-14 新建，分支 `main`，基线 a0a4012）。
看板更新属于文档包内容变更，收口时随其他文档更新一并重建。**收口顺序（2026-11-14 用户新原则）：语法自检 → git 提交（卡片改毕必提交）→ zip 重建 → 线上重部署。重建一律用 `tools/rezip-docpackage.ps1`（PowerShell，工作区根目录执行）：**

```bash
cd <工作区根>
powershell -ExecutionPolicy Bypass -File tools/rezip-docpackage.ps1
```
> 2026-11-14 注：脚本已改为按自身位置（`$PSCommandPath`）推导工作区根，不再硬编码机器路径，任意机器/目录布局可直接执行。

> ⚠️ **禁用 `tar.exe`/bsdtar 重建**（2026-11-12/13 两轮实测）：中文 locale 下会把非 ASCII 条目名写成 GBK，`-f` 输出文件名同样被 GBK 化，且会把 `.zcode/` 会话状态一并打包泄漏。`rezip-docpackage.ps1` 自带 BOM 勿剥；辅助校验 ps1 一律纯 ASCII + 通配路径（中文路径进按 ANSI 解析的 ps1 必炸）。
> 看板线上镜像 <https://musicgraphy-progress-ohqn.zai-ai.site>：`progress-data.js` 更新后需重部署才反映线上（stage 三文件重建 + 部署，程序见工作区根 `AGENTS.md` §4）。
